# Flashes live cinematic looks

## Contract

Original, Noir, 35mm, After Hours, Chrome, Amber, Dusk, Coastal, Velvet and Silver grade live previews and captured stills locally. The 23 October camera revision moves look selection before capture and preserves the chosen look and strength through capture, camera switching and retakes. There are no face effects, reshaping, stickers, borders, remote image processors, new dependencies or services. Soft Flash diffusion is excluded pending measured device evidence. No server, moderation, consent, expiry, one-look or access-control behavior changes.

- Original and strength zero reuse the ungraded capture's existing JPEG bytes.
- The same deterministic sRGB pixel kernel powers the live canvas, compact still-thumbnail strip and selected full-size export. Live controls use a compact horizontally scrollable name strip. Thumbnails show the full-strength direction; the main preview shows the selected strength.
- Strength is bounded to 0–100. Grain is deterministic and does not move when the photo is re-rendered.
- A full-size encoded Blob is previewed, and that exact Blob's bytes become the upload File. Send is unavailable until its image has loaded, consent is checked and comparison is off. Server-side WebP recompression means the subsequently stored image is not promised to be pixel-identical.
- Holding the photo compares the Original; a separate keyboard/screen-reader-operable button toggles the same comparison. Pointer cancellation clears temporary comparison.
- Live preview and capture preserve the entire delivered sensor frame with containment instead of cropping to the screen. Header and controls sit outside the image. The camera request no longer imposes a portrait width/height combination and prefers native, uncropped frames. No digital zoom is requested. Browser/hardware lens selection is not controlled or claimed verified. The front-camera preview and saved photo intentionally mirror once. Output retains the existing 1600-pixel maximum edge without upscaling.
- Live processing is bounded to a 480-pixel maximum edge and targets 30 fps, adapting to each frame’s measured draw/read/grade/write cost to leave time for input and painting; it skips hidden documents, stops on capture/close and releases its canvas. A failed live look disables the shutter until Original or a working look is selected. This avoids relying on unsupported Safari canvas filters. A Node 22 cloud-runner measurement at 480×270, after ten warm-up frames and across 30 measured frames per look, observed 1.26–3.18 ms p95 pixel-kernel cost. This excludes browser canvas transfers/compositing and is not an iPhone performance measurement. The adaptive browser timing includes those canvas operations, but actual physical-device smoothness remains unverified.
- Still-photo work is debounced 100 ms and yields every 32,768 pixels. Changes, retakes and close abort stale render jobs; their completion cannot become an upload. Scratch canvases are released and Blob URLs revoked.
- Both editor and existing Flash viewer explicitly set image containment to override the framework’s inline cover default, keeping the saved frame visible without a second crop.
- After capture the editor keeps the complete saved frame visible above the controls, with a scrollable thumbnail strip. Compact landscape places controls alongside the photo.

## Evidence and remaining gate

The focused Node tests exercise the actual grading functions and camera component event/effect ordering, including source invariance, strength endpoints, deterministic chunked grain, uncropped/mirrored capture, stale completion, retry, repeated selection, exact preview/upload Blob parity, consent, retake and close cleanup. Live-renderer coverage checks shared grading, bounded dimensions, throttling, hidden-page suspension, changes, mirroring and failure fallback. They do not establish native browser rendering or hardware camera performance.

`tests/e2e/flash-camera.spec.ts` supplies isolated real-browser journeys for Chromium desktop/mobile and WebKit mobile. It mocks camera sensor input, not the renderer, so canvas encoding, image decode, upload bytes, layout, accessibility and pointer behavior remain real. Coverage includes all ten looks, selection before capture, full-frame edges, mirrored live and saved pixels, retained strength and selection, a 320×568 viewport and 844×390 landscape. Mobile Chromium uses real browser-protocol touch-start/cancel; WebKit’s available harness covers a real tap and mouse-hold/synthetic cancellation, not native held-touch capture. These require an environment capable of launching the configured browsers; local browser execution is currently blocked by the environment. A physical iPhone Safari/PWA check remains separate from emulation, especially front/rear cameras, orientation, resume, low light, repeated retakes and memory pressure.

`scripts/preview-flash-filters.mjs` makes a repeatable code-output contact sheet from a provided image and explicit crop. The first artifact uses only the Original panel of an existing fictional visual study. It invokes the actual pixel kernel and Sharp JPEG encoding, not browser canvas encoding. The artifact is neither a production UI screenshot nor device-performance evidence.
